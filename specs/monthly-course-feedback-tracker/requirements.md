# 月度课程反馈问卷跟踪系统 — 需求规格

状态：已确认（2026-09-17）  
目标平台：腾讯云 CloudBase  
目标用户：教务老师

## 1. 背景与目标

当前课程数据和问卷结果均在飞书多维表格中，但教务缺少一个按月生成问卷任务、分发二维码、跟踪填写状态并衔接现有老师反馈报表的统一工作台。

系统应以“课程月份 + 学生 + 老师”为一份问卷任务。一个学生在同月由同一位老师教授多个课程时，只生成一份任务，并在任务中合并展示课程名称。每份任务必须有稳定且唯一的 `任务ID`，用于匹配问卷提交，禁止以姓名作为唯一匹配键。问卷在课程月份的下一个自然月收集，例如 2026 年 9 月收集 2026 年 8 月课程反馈。

## 3. 用户故事

1. 作为教务老师，我希望选择一个月份并从课表生成问卷任务，以便知道该月总共需要收集多少份反馈。
2. 作为教务老师，我希望按老师、学生、课程和状态筛选任务，以便快速安排发送和催收。
3. 作为教务老师，我希望每份任务都有可打开、复制和下载的二维码，以便把正确的专属问卷发给学生。
4. 作为教务老师，我希望问卷提交后任务自动变为“已填写”，并看到提交时间，以便无需人工对账。
5. 作为教务老师，我希望可以把任务改为“未发、已发、已填写、拒绝填写”，并保留修改记录，以便反映实际跟进状态。
6. 作为报表使用者，我希望将同期课表和答卷无重复地交给现有老师反馈系统，以便继续生成评分与看板。

## 4. 功能需求与验收标准

### R1. 月度任务生成

- 当教务选择收集月份并执行同步时，系统应读取上一个自然月的完整课表和关联学生资料。
- 当系统展示或导出任务时，应同时标明课程月份与收集月份，不得用一个含混的“月份”字段代替两者。
- 当同一学生与同一老师在同月有多条有效课程记录时，系统应只生成一份任务，并合并去重后的课程名称。
- 当再次同步同一月份时，系统应按稳定任务 ID 幂等更新，不得生成重复任务，也不得覆盖教务已手动修改的有效状态。
- 当课表缺少学生、老师、课程或时间等关键数据时，系统应跳过无法可靠生成的任务，并显示可定位到源记录的错误清单。
- 当课程被判定为无效课程时，系统不得把该记录用于创建任务；有效课程规则须在进入设计前确认。

### R2. 专属链接与二维码

- 当任务创建时，系统应生成唯一任务 ID 和专属问卷链接，并预填学生姓名、老师姓名及任务 ID。
- 当预填值不在问卷允许选项中时，系统应先阻止该任务进入可发送状态，并明确显示未匹配字段，不得生成看似可用但实际预填失败的二维码。
- 当教务查看任务时，系统应支持打开问卷、复制链接、单张下载二维码。
- 当教务选择多条任务时，系统应支持批量下载二维码；导出物应包含可辨识的学生、老师、月份和任务 ID。

### R3. 状态管理

- 系统应支持四个状态：`未发`、`已发`、`已填写`、`拒绝填写`；新任务默认为 `未发`。
- 当教务手动修改状态时，系统应记录修改时间和修改来源。
- 当收到匹配任务 ID 的有效答卷时，系统应自动将任务改为 `已填写` 并记录提交时间。
- 当任务已标记为 `拒绝填写` 后又收到有效答卷时，系统应以答卷事实为准改为 `已填写`，并保留原状态变更记录。
- 当同一任务收到多次答卷时，系统应标记重复提交并保留全部答卷引用，不得重复增加已填写任务数。

### R4. 自动同步与校验

- 当飞书答卷新增时，系统应在约定时效内同步任务状态；同时应提供定时全量对账作为事件遗漏时的补偿机制。
- 当答卷没有任务 ID、任务 ID 不存在或关键字段缺失时，系统应进入异常列表，不得仅凭姓名自动绑定。
- 当飞书接口鉴权失效、限流或返回异常时，系统应显示最近成功同步时间和可操作的错误提示，并支持安全重试。
- 当任务生成前发现学生或老师选项与问卷不一致时，系统应给出同步或修复清单；具体采用“自动维护问卷选项”还是“将问卷姓名字段改为文本”须在设计前确认。

### R5. 工作台与统计

- 当教务打开工作台时，系统应默认显示当前收集月份及其对应的上一个课程月份，并展示任务总数、未发数、已发数、已填写数、拒绝填写数及完成率。
- 当教务筛选月份、老师、学生、课程或状态时，列表和统计应保持一致。
- 当任务数量超过单页容量时，系统应提供分页或虚拟滚动，且批量操作应清楚标明作用于当前页还是全部筛选结果。
- 当教务导出任务清单时，系统应导出当前筛选范围及任务 ID、月份、学生、老师、课程、状态、问卷链接、提交时间和异常信息。

### R6. 与老师反馈系统衔接

- 当教务选择已完成的收集月份时，系统应能够产出“上一个自然月课表 + 当前收集月答卷”的兼容 CSV，且字段和日期口径通过现有测试样例验证。
- 当导出完成时，系统应提供前往老师反馈系统的入口，并清楚提示仍需上传哪些文件。
- 若业务确认需要“一键生成报表”，系统应新增受鉴权保护的服务间接口，而不是依赖浏览器本地存储或自动操纵另一个网站页面。

### R7. 权限与审计

- 当未登录用户访问管理页面或接口时，系统应拒绝读取学生、老师、问卷状态等数据。
- 当已授权教务访问系统时，系统应只暴露完成工作所需的信息，不显示飞书密钥或 CloudBase 密钥。
- 所有手动状态修改、月度同步和批量操作应记录操作者、时间、操作类型和结果。
- 飞书 App Secret 和其他凭据必须存储在 CloudBase 服务端密钥或环境变量中，不得下发到浏览器、写入仓库或构建产物。

### R8. 可用性与运行保障

- 当同步部分失败时，系统应以批次为单位展示成功、跳过和失败数量，并允许只重试失败项。
- 当重复触发生成或同步时，系统应保持幂等，不得重复创建任务或倒退状态。
- 系统应为课表解析、任务去重、链接编码、状态迁移、重复答卷和异常答卷提供自动化测试。
- 上线前应在独立测试环境验证，不直接在生产数据上试错。

## 5. 数据范围与非目标

### 本期范围

- 飞书课表读取、学生关联解析、月度任务生成。
- 问卷专属链接、二维码、状态跟踪、筛选统计、异常列表和导出。
- 飞书答卷自动同步及定时对账。
- 与现有老师反馈系统的兼容数据导出和入口跳转。

### 暂不包含

- 重写现有老师反馈评分算法和看板。
- 向学生自动发送飞书、微信或短信消息；本期只记录“已发”状态，除非另行确认发送渠道和授权。
- 修改课表原始业务数据。
- 将学生个人信息复制到公开静态文件或 Git。

## 6. 已确认的业务口径

1. 以收集月份为工作台入口，读取上一个自然月的完整课表；例如 9 月收集 8 月课程反馈。
2. 所有带 `临时取消` 的课程不计入“上过课”。
3. 默认排除申请会议、申请咨询、普通咨询等非授课项目；异常课程类型进入同步结果供教务复核。
4. 保留现有问卷下拉字段，生成任务前把课表中的缺失姓名追加到选项中并复核，只追加、不删除历史选项；任务 ID 是唯一匹配键。
5. 采用“飞书事件实时同步 + 每 5 分钟补偿对账”。
6. 首版导出兼容 CSV 并跳转现有反馈系统；一键生成看板作为后续增强。
7. 二维码由项目代码生成，不接第三方二维码 API；单张下载 PNG，批量异步生成 ZIP。
8. 开发和测试使用 `jingshi-test-d5gp401i44a0fa7a7`，生产环境在上线前另行确认。

## 7. 开发所需凭据与配置

以下内容必须由业务方在进入联调前提供或确认：

- 飞书自建应用的 `App ID` 与 `App Secret`，并授予所需多维表格读取、任务表写入及事件订阅权限。它们只写入 CloudBase 服务端密钥。
- 课程 Base token、反馈 Base token、课表/学生/答卷/任务表 ID（当前已从链接核实，可作为环境配置，不作为密码处理）。
- 问卷分享 token 和最终采用的姓名字段方案。
- CloudBase 测试环境与生产环境 ID、首批管理员和登录方式。
- 若首版要求自动发送二维码，还需提供发送渠道、收件人字段及对应授权；否则该能力不在本期范围。

> 说明：飞书链接中的 Base token（通常也叫 `app_token`）只能定位多维表格，不能替代服务端 API 鉴权。部署到 CloudBase 后仍需飞书自建应用的 App ID / App Secret；本地 `lark-cli` 的用户登录凭据不会复制到云端。

## 8. 建议的成功指标

- 同一月份重复同步 3 次，任务总数和任务 ID 保持一致。
- 所有可发送任务的二维码打开后，学生、老师和任务 ID 均正确预填。
- 正常答卷在约定同步时效内变为“已填写”，无任务 ID 的答卷 100% 进入异常列表。
- 月度任务数、四类状态数和导出清单可相互复算。
- 导出的两份 CSV 能被现有老师反馈服务成功处理，且不新增未识别日期或字段错误。
