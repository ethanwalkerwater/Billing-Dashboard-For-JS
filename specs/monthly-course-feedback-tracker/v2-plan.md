# 月度课程反馈 V2：单表工作台 + 姓名匹配

状态：任务 1–8 全部完成并在浏览器验证（2026-09-17）
前置：V1 已部署到测试环境，258 份 2026-09 任务已生成，教务账号可登录。

## 0. 诊断结论

### 0.1 「同步答卷后一个都没有」

不是同步失败，是 V1 的绑定规则太严：只按 `任务ID` 绑定，而 9 月 182 份答卷全部通过旧的公共分享链接填写，`任务ID` 为空，0 份能绑定，「已填写」恒为 0。

用真实数据验证按（学生姓名, 老师姓名）匹配的可行性：

| 9 月 182 份答卷 | 数量 |
|---|---|
| （学生, 老师）精确对上一份任务 | 168（92%），覆盖 258 份任务中的 164 份 |
| 老师名 `Valentina 林` vs 任务 `Valentina Lin` | 10 |
| 老师名 `马老师` vs 任务 `马怡婷` | 1 |
| 学生名变体 `Arwen姚若澜` / `顾子言` | 2 |
| 组合不是本月任务 | 1 |

加两条老师别名后 179/182（98%）。需求文档 §2 的「88 位学生仅 19 位匹配」说的是下拉选项 vs 课表，不是实际答卷。

**业务方决定（2026-09-17）：不往飞书反馈表加任何字段，不用任务 ID，姓名匹配是唯一机制。** 规范化后精确相等 + 别名表，不做模糊匹配。对不上的列出来给教务手动绑定。已实现并用 9 月数据验证：182 份 → 177 对上、4 重复、1 对不上（该组合 8 月课表里不存在）。

### 0.2 「页面要切 tab 看不同表格」

V1 的任务表只显示任务状态，答卷信息在另一个「同步结果」面板里。教务想要的是**一行一个学生-老师对，状态一眼可见**。

### 0.3 「设计粗糙」

V1 是手写 CSS。仓库里没有任何 app 用 Tailwind / shadcn，切到 shadcn 意味着给这个 app 加 Tailwind + Radix。用户明确要求，接受。

## 1. 数据模型变更

### `feedback_tasks` 新增列

| 列 | 说明 |
|---|---|
| `student_response_id` | 学生本人那份答卷的 record id（可空） |
| `parent_response_id` | 家长那份答卷的 record id（可空） |
| `bound_by` | `name` / `manual` / null ——怎么绑上的 |

一行任务直接带着「学生填了没 / 家长填了没」，列表不用再 join。

### `status` 派生规则

| 显示状态 | 条件 |
|---|---|
| 未发 | `status=unsent` |
| 已发 | `status=sent` 且无答卷 |
| 已评 | 有学生或家长任一答卷（`status` 自动变 `completed`） |
| 拒绝 | `status=declined` 且无答卷 |

子标签：学生已评 / 家长已评 / 双方已评 / 姓名匹配（bound_by=name）。

### 新表 `feedback_name_aliases`

```sql
kind text check (kind in ('teacher','student')),
alias text,           -- 问卷里出现的写法：Valentina 林
canonical text,       -- 课表规范名：Valentina Lin
primary key (kind, alias)
```

首批种子：`Valentina 林 → Valentina Lin`，`马老师 → 马怡婷`。教务在设置页可维护。

### `feedback_responses` 新增

`bound_by text`，`identity text`（学生本人 / 家长）。

## 2. 匹配算法（已实现，`reconcile-responses.ts`）

```
for 每份本月答卷（按提交时间排序）:
  1. 有手动绑定记录（bound_by=manual）→ 用它，重跑不覆盖
  2. 否则 别名表规范化后 (学生, 老师) 在本月任务里精确查找
     - 命中 → bound_by='name'
     - 未命中 → unlinked，带原始姓名进「对不上的答卷」列表
  3. 按身份写到 student_response_id / parent_response_id；同一身份第二份 → duplicate
  4. 任一位置有答卷 → task.status = completed
```

不写飞书。问卷下拉缺的姓名只提示不追加。

## 3. 单表工作台

### 3.1 列

| 列 | 内容 | 可排序 | 可筛选 |
|---|---|---|---|
| ☐ | 行选择 | | |
| 学生 | 姓名 + 任务 ID 尾号 | ✓ | 搜索 |
| 老师 | 规范名 | ✓ | 多选 |
| 课程 | 合并后的标签 | | 搜索 |
| 状态 | 未发 / 已发 / 已评 / 拒绝 徽章 | ✓ | 多选 |
| 谁评了 | 学生 ✓ / 家长 ✓ / — | | 筛选「学生未评」「家长未评」 |
| 绑定 | 任务ID / 姓名 / — | | 筛选「姓名匹配」需复核 |
| 最近动作 | 发送 09/17 20:43 / 学生已评 09/12 | ✓ | |
| 操作 | 二维码 / 复制链接 / 手动绑定 | | |

### 3.2 顶部

- 收集月份选择器（保留双月份口径）
- 四个可点击统计卡：**应发 258 · 已发 256 · 已评 164 · 未评 94**，点击即筛选
- 「本月收到反馈 182 份，其中 168 已绑定、14 对不上」一行文字 + 展开
- 操作：生成任务 / 同步答卷 / 批量二维码（选中数）

### 3.3 批量操作（选中行后出现浮动栏）

- 标记已发 / 标记拒绝 / 退回未发
- 下载选中二维码 ZIP
- 导出选中为 CSV
- 明确标注作用范围：「已选 N 行（当前筛选 M 行）」+ 「选中全部筛选结果」

### 3.4 侧栏抽屉（点行）

- 二维码卡片 + 单张下载 + 复制链接
- 该任务的全部答卷（学生/家长，提交时间，绑定方式）
- 手动绑定：从「对不上的答卷」里选一份绑到这行
- 状态变更历史（来自 audit log）

### 3.5 「对不上的答卷」面板

替代 V1 的 SyncPanel。列出 unlinked 答卷的原始学生名/老师名/身份/时间，两个动作：
- **加为别名**（一键把 `Valentina 林 → Valentina Lin` 写进别名表并重跑匹配）
- **手动绑定到任务**（选一行）

### 3.6 视觉

shadcn/ui 组件：`Table`（+ TanStack Table 做排序/筛选/选择）、`Badge`、`Button`、`Checkbox`、`DropdownMenu`、`Sheet`（抽屉）、`Dialog`、`Command`（搜索）、`Toast`。
Tailwind + `tailwind-merge` + `class-variance-authority`。保留现有色板（墨黑 / 纸白 / 学院蓝 / 行动青 / 完成绿）映射到 CSS 变量。中文字体继续用系统栈。

### 实施中改的决定

- **没有引入 TanStack Table**。装上才发现是 v9，API 全新（`useTable` + 手动启用 features）。
  258 行表格只需要排序/筛选/选择，自己写十几行比学新 API 更省，风险也更低。
- **二维码「对不上的答卷」从同步明细里移到了页面顶部横幅**，并加了自动诊断，
  因为教务需要的不是"有几条对不上"，而是"这条我该做什么"。

## 5. 已确认的决定

1. 姓名匹配是唯一机制，不用任务 ID，不改飞书表。✅
2. 学生 + 家长任一方填了即算「已评」，两列都显示。
3. 引入 Tailwind + shadcn（用户要求）。
4. 别名维护放在「对不上的答卷」面板一键添加；手动绑定放在行抽屉。

## 6. 不做的事

- 模糊 / 拼音 / 编辑距离匹配。对不上的靠别名和手动绑定，不猜。
- 回写飞书任务表镜像。网站就是任务表。
- 自动给学生发送二维码。仍是教务手动发，只记状态。
