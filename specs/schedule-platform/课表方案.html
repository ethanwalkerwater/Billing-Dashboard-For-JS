菁仕课表服务方案

现状摸底 · 方案对比 · 成本与难度 · 功能脑暴 · 分期路线 ｜ 2026-10-05

结论先说
  1. 能做，而且不贵。学校规模很小（每月约 1,400 节课、30 多位在课老师、约 100 名在读学生），服务器费用一年几百元级别；真正的钱和时间花在微信资质和开发工时上。
  2. 先别替换飞书。第一步只做「微信里看课表 + 提反馈」的一层，排课仍在飞书里改。飞书现在还承担冲突提醒、日历同步、账单和老师收入的数据源，一次性换掉风险最大、收益最小。
  3. 技术栈沿用 CloudBase（腾讯云开发）。仓库里雅思正向率已经是「飞书 → CloudBase → 网页」这一套，照搬即可；而且微信网页授权和小程序都要求备案域名，Vercel 在这条路上走不通。
  4. 马上启动不花开发时间的事：服务号认证、域名 ICP 备案、微信开放平台绑定。这三件要排队 1–3 周，是整个项目的关键路径。

飞书现在已经做好的部分（自建时要补齐）

  • 冲突提醒：课表有「排课冲突提醒」「时间地点冲突提醒」两个公式字段。
  • 老师日历同步：有「老师-日历」人员字段、「日历同步」勾选框和「日历 ID / 日程 ID」，老师那边已经同步到飞书日历。
  • 重复排课：有「每周重复」「每天重复」按钮。
  • 时差：有「时差」「当地上课时间 / 当地下课时间」，海外学生能看到当地时间。
  • 网课会议：「会议信息」+「会议信息报错」。
  • 计费：课程单价、总价、临时取消（0h-70% / 2h-50% / 6h-30% / 病假-0%）、价格优惠，下游连着课时账单和老师收入。
  • 调课和请假：独立的「调课和请假」表，来自飞书审批（目前 46 条，用得不多）。

敏感字段暴露风险同一张表里有单价、总价按视图分享时，要靠人工确保价格列被隐藏。（需要确认现在的分享方式）

2. 三条路怎么选

A. 买现成教务 SaaS

小麦助教、校宝这一类

✅ 排课、家校端、微信通知开箱就有

❌ 现有计费规则（取消比例、老师分成 20%/7%）、雅思正向率、老师反馈评分都要迁过去或者丢掉；按年付费，具体价格要询价；数据在别人家

B. 飞书做底，自建微信层 推荐

管理员继续在飞书里排课

✅ 1–2 周就能上线可用版本；不碰计费链路；风险最低

✅ 先把「看、提醒、反馈、给家长出方案」这些真正痛的地方解决掉

❌ 飞书本身的问题（选项混乱、视图多）只能靠数据清理缓解

C. 全部自建，替换飞书

B 跑顺之后再决定要不要走

✅ 完全掌控，排课体验可以做到最好

❌ 排课编辑器（拖拽、重复、冲突、时差）是最难的部分，等于重做飞书已经免费给你的东西；账单和收入的数据源都要跟着迁

建议：先走 B，C 当成第三阶段的可选项，设好进入条件再说（见第 6 节）。

3. 推荐架构（B 路线）

关键设计点

  • 同一时间只有一个数据源。课表只在飞书里改。新系统只读课表，自己只存「反馈单、排课方案、身份绑定」。这样就没有双写冲突。
  • 身份绑定靠邀请链接。管理员给每个人生成一次性绑定链接或二维码，打开后用微信授权，把 openid 绑到「老师信息 / 学员信息」里的那条记录上。不靠名字匹配。
  • 家长单独算一种身份。真正用微信看课表的往往是家长：一个学生可以绑多位家长，一位家长可以切换多个孩子。
  • 第一天就存 unionid。服务号网页和小程序拿到的 openid 不一样。把两者都挂到微信开放平台下，用 unionid 关联，以后上小程序时用户不用重新绑定。
  • 字段按身份裁剪。学生和家长那一端的接口根本不返回单价、总价、老师分成，不是在前端藏起来。
  • 日历用 ICS 订阅链接。每位老师一条私有的 webcal:// 链接，iPhone、Mac、Google、Outlook 日历都能订阅并自动更新。现有的飞书日历同步继续保留，两种方式并存。

5. 功能脑暴

优先级标签：P0首版必须 P1第二阶段 P2小程序 / 进阶 想法有空再说

管理员

  • P0反馈 / 请假待办台：一处看全部待处理，处理结果自动通知本人
  • P0邀请绑定管理：生成链接或二维码，看谁还没绑定
  • P0数据健康检查：未知课程类型、老师名写法不一致、缺学生的课
  • P1排课方案：给家长出 A / B / C 几套时间方案，家长在微信里选，确认后自动写进飞书
  • P1课表海报：一键生成某个学生的本周课表图片，方便发家长群
  • P1变更日志：谁、什么时候、改了哪节课（基于同步快照对比）
  • P2老师空闲时间热力图：排课时直接看谁有空
  • P2课时余额预警：联动课时账单，余额不足时提醒续费
  • 想法AI 排课助手：「给某学生每周二、四晚上找两小时雅思，避开考试周」→ 自动给出候选方案

老师

  • P0今日 / 本周课表：地点、学生、会议链接一键进入
  • P0日历订阅链接（ICS），飞书日历同步保留
  • P0调课申请：选中某节课 → 填原因 + 建议的新时间
  • P1前一晚收到次日课程汇总，课程变动实时推送
  • P1课后反馈入口：直达现有的课程反馈表
  • P2登记每周可用时间，供排课参考
  • P2本月课时汇总：只看课时，金额仍在老师收入报表里

学生 / 家长

  • P0本周课表，海外学生显示当地时间
  • P0请假 / 调课申请，提交前明确提示扣费：距上课 >6h 扣 30%、2–6h 扣 50%、<2h 扣 70%，病假 0%
  • P0家长一人管多个孩子，切换查看
  • P1收到排课方案 → 在微信里选择并确认
  • P1课前提醒、变动通知、请假审批结果通知
  • P2入口整合：雅思成绩、月度家长报告、课时余额
  • 想法课后一键评价，直接喂给老师反馈评分

核心流程：请假 / 调课

学生或老师在微信里点某节课→ 选「请假」或「调课」，看到扣费提示→ 提交，写入飞书「调课和请假」表→ 管理员在飞书里改课表→ 同步检测到变动→ 服务号通知所有相关的人

核心流程：排课方案

管理员录入 2–3 套候选时间→ 系统校验老师和学生有没有冲突→ 家长在微信里收到链接→ 家长选定一套→ 管理员确认→ 自动在飞书里批量建课

7. 风险与注意

  • 域名和资质是关键路径。没有备案域名和认证服务号，微信内登录做不了。今天就该开始办。
  • 不要用 Vercel 承载微信端。*.vercel.app 在国内访问不稳定，也不能做网页授权域名。CloudBase 的默认测试域名在微信里还会出拦截页，必须绑自己的备案域名。
  • 模板消息只能发服务通知。课程变动、上课提醒合规；营销、招生内容不能发，否则会被封。
  • 数据质量决定通知准不准。如果老师名或学生关联不规范，通知会发错人。上线前先跑一遍数据健康检查。
  • 隐私。学生端和家长端只返回自己的课；单价、分成字段在服务端就要去掉。分享链接要带过期时间。
  • 同步延迟。5 分钟一次的增量同步对看课表够用；如果对通知时效要求更高，再接飞书事件订阅。

8. 需要你拍板的问题

  1. 学校是否已有认证服务号？主体是不是企业？
  2. 学生这一端，实际用微信的是学生本人还是家长？还是两者都有？
  3. 老师是不是都在用飞书日历？有没有人更希望用 iPhone 或 Google 日历？
  4. 现在学生和家长是怎么拿到课表的？分享视图、截图，还是老师发消息？
  5. 「排课方案给家长」现在是怎么做的？一次一般给几套方案？
  6. 能不能接受先把「课程类型」拆成「科目 + 备注」？这会影响雅思正向率里的科目映射，需要同步调整。
