# 课堂复盘上线规格

规格已验收。工作入口 https://app.jsjy.asia/fupan/ 。本地规格跟踪，真实课程内容只在授权运行环境读取。代码评审与上线验证记录见 [本次复盘](./RETRO.md)。

## 用户问题和交付目标

教学主管要从菁仕课堂已有转写找到需要核实的片段，回听原话、记录判断并追踪带教结果。上线页面覆盖待处理、课程、老师三个入口，以现行课堂管理交互稿和菁仕试点 PRD 为准。

## 决策地图

| 决策 | 已确定的处理 |
|---|---|
| 谁能看 | 采用飞书真实身份与独立主管名单，每次授权。名单初始为空，名单由业务稍后指定。 |
| 如何节省资源 | 转写沿用既有入库与事件分析。列表按需加载，点击播放才签短时地址；零新增定时器和轮询。 |
| 复核口径 | 优先级独立于类目，模型结果初始待复核；确认、排除、转办、跟进结果保留操作人、时间和历史；只计人工确认的老师问题。 |
| 数据来源 | 使用菁仕实际排课、录音、转写、已有分析。无来源的指标明确标记缺失；会议及合并反馈不重复计课。 |
| 发布边界 | 复用共享 classroom-api 的现网代码基线和独立静态目录。保留已有录课行为。空名单时只开放登录入口。 |

## 用户故事与验收

1. 作为主管，我能用飞书登录，并在待处理中按紧急程度、待复核／跟进中／已关闭找到事项。
2. 我可以从原话及多个证据时间戳进入对应课程，检查逐字稿上下文，跳转、暂停和回听。
3. 我可以确认、排除或转办，记录原因、负责人和跟进结果；刷新后保留处理历史。冲突需刷新。
4. 我能按日期和老师查看课程、区分录音和分析状态，并从列表或老师档案抽听。
5. 我能查看有数据依据的课程概要、教学模式、时间档案和听课记录，给课程记录亮点、问题或建议。
6. 我能查看老师的本月课程数、人工确定问题数和近期课程，以既有老师身份登记年级和班级。
7. 作为未授权用户，我无法通过链接、伪造身份或公开报告读取课程内容、生成播放地址或提交操作。
8. 作为运维，我能独立发布和回退这个入口，沿用现有转写处理，不额外启动周期任务。

## 接口与测试约定

入口 /classroom-api/fupan/；服务端负责权限与输入校验，私有数据响应禁缓存。UI读取服务端 JSON，静态包只含程序。用虚构夹具测全流程、状态转换、版本冲突、转写修订、越权、真实数据字段缺失。线上验证入口、飞书跳转、一次性浏览器绑定、拒绝名单外会话、数据库隔离和原有服务。正式身份通过后生成限路径 HttpOnly cookie，新增录音仍沿用原分析管线。主管实名授权待名单，正式身份验收单列。

## 运维口径

按每月 22 天、每天 50 次操作、每次约 3 个 API 调用估算，网关约 33 点，函数另按实际时长与内存。若每天额外唤醒两个独享的数据库五分钟格，约 627 点/月；与录课活跃格重合则不重复。录音出网和既有分析费用按实际用量，保留现有录音生命周期。无实课内容外发或静态托管，无新增通知、同步或模型任务。
