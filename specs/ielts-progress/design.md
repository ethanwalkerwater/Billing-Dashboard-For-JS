# 雅思正向率系统 设计

2026-10-01 与业务方逐节确认。

## 目标

教务能看到每位老师的雅思学生正向率（本次实考比上一次成绩高），按时间、按科目对比。数据流转清晰不漏，老师录入简单，服务器消耗低，页面不卡。

## 业务口径（已确认）

| 项 | 口径 |
|---|---|
| 成绩 | 听力 / 阅读 / 写作 / 口语分别录入，0–9，步长 0.5；可只考部分科目 |
| 成绩类型 | 基线（入学模考或带来的旧成绩，不需核验）、实考（需上传成绩单，教务核验后才计入） |
| 配对 | 每次**已核验的实考**，每一科都和该学生**上一次该科有分的成绩**比（基线或更早的已核验实考） |
| 先后 | 按「考试日期」排，不按提交时间；同一天基线排在实考前 |
| 结果 | 提分 = 正向；持平、下降都不算正向，三者分开统计 |
| 授课老师 | 课表里该学生、该科目，上课日期满足 `上一次成绩日期 ≤ 上课日期 < 本次考试日期`，非临时取消 |
| 多位老师 | 每位教过的老师都算这条样本 |
| 整体统计 | 按「实考 × 科目」去重，一条样本只算一次 |
| 小样本 | 老师样本 < 5 条灰显、不参与排名 |

### 课表「课程类型」→ 科目

| 课程类型 | 科目 |
|---|---|
| 含「刷题」「试听」「考试」「模考」「笔考」 | 不计入 |
| 恰好是 `雅思` | 四科全部（老师负责全科） |
| 含「听力」「阅读」「写作」「口语」（如 `雅思写作`、`雅思提高班-写作`、`雅思听力&口语`） | 出现的科目 |
| 其他含「雅思」的（如 `雅思英语`） | 无法识别，同步结果里列出，进待处理 |

## 录入：飞书「雅思成绩」表

建在课表所在多维表格（`Xb34bXSVRaQk7ysfAQScPZp5nPh`）里，一次考试一行：

| 字段 | 类型 | 规则 |
|---|---|---|
| 编号 | 自动编号（主字段） | |
| 学生 | 单向关联 → 学员信息 | 必填，只能选 |
| 成绩类型 | 单选：基线 / 实考 | 必填 |
| 考试日期 | 日期 | 必填 |
| 听力 / 阅读 / 写作 / 口语 | 单选 0…9（步长 0.5） | 可空 |
| 成绩单 | 附件 | 实考必传 |
| 提交人 | 创建人 | 自动 |
| 已核验 | 复选框 | 仅教务，表单不显示 |
| 备注 | 文本 | |

老师只用一个表单视图「老师录入雅思成绩」。学生是关联字段，系统拿记录 ID 和课表的「学生」关联字段精确对上，不做姓名匹配。

## 架构

沿用 `teacher-income-alert` 的形态：CloudBase PostgreSQL + 单云函数 + Vite/shadcn 前端，`jsjy` 登录，`feedback_admins` 白名单。

```
飞书表单 → 雅思成绩表 ─┐
                       ├─ 云函数 ielts-api（按钮 / 每日定时）→ ielts_snapshots.feishu（一行 JSON）
课表（只拉雅思课）─────┘
历史 CSV → scripts/import-legacy.ts（一次性）→ ielts_snapshots.legacy
浏览器：读两行快照 → domain/progress.ts 现算配对、归属、统计 → 图表
```

省资源的几个决定：

- 课表用飞书服务端过滤 `课程类型 contains "雅思"` + 只取 5 个字段：实测 1731 行、约 20 秒，比全表 15k 行少 9 成。
- 数据库只存**一行快照**（成绩 + 雅思课 JSON，约 200KB）。同步是一次 upsert，天然原子：飞书没读全就报错，旧快照原样保留。页面打开只发一个查询。
- 配对与统计在浏览器里用纯函数现算（几百条成绩 × 一千多节课，毫秒级），核验状态一改、同步后所有数字跟着变，没有过期的派生表。

## 待处理（不悄悄丢）

| 情况 | 处理 |
|---|---|
| 飞书字段缺失或改名 | 同步报错写明字段，保留旧快照 |
| 学生没选 / 选了多个、没有考试日期、分数不合法、四科全空 | 该条不计入，列为「录入有误」 |
| 同一学生、同一天、同一类型两条 | 两条都不计入，列为「疑似重复」 |
| 实考没有成绩单 | 不计入，列为「缺成绩单」 |
| 实考未核验 | 不计入、也不作为下一次的「上一次成绩」，列为「待核验」 |
| 某科之前没有成绩 | 列为「缺少上一次成绩」 |
| 两次之间该科无人授课 | 列为「无授课老师」 |
| 课表里无法识别科目的雅思课 | 列出课程类型和条数 |

## 历史数据

`teacher_score_records_*.csv`（119 行）已是「学生 × 科目 × 老师」展开后的配对结果，无基线日期：

- 按（学生, 科目, 基线分, 实考分）合并成一条样本，老师取并集，日期取最早 `createdAt`。
- 老师名统一成课表写法：`Kevin → Kevin Liu`、`Valentina 林 → Valentina Lin`；对不上的名字导入直接失败。
- 视为已核验，来源标「历史」，可单独筛选。

## 看板（细节后续可再调）

单页：待处理横幅 + 同步按钮 → 筛选（考试日期区间 / 科目 / 老师 / 来源）→ 统计卡（样本数、正向率、平均提分、持平、下降）→ 老师对比（100% 堆叠条：提升 / 持平 / 下降，按正向率排序，标 n）→ 老师 × 科目矩阵 → 按月趋势 → 明细表（点击图表筛明细）。

暂不做：导出、老师自助查看、四科平均分正向率。

## 测试

`tests/progress.test.ts`：科目映射每一行、飞书真实字段形状解析、C 规则配对（含跳过未核验）、授课窗口边界、多老师计入与整体去重、每类待处理、历史 CSV 合并。另用历史 CSV 手工核对两位老师的正向率。
