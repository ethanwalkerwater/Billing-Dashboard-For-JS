# 老师档案 + 生日祝福（teacher-birthday）设计

日期：2026-10-09

## 目标

1. 教务在飞书「老师数据主表」维护老师档案；首批录入官网「名师团队」22 位老师（不含「菁仕严选老师」）。
2. 老师生日前 3 天 09:00，把预填老师姓名的祝福问卷私信发给教务（华心晨、Tinko），由教务转给学生和同事。
3. 生日当天 09:00，在老师群发生日卡片，@ 寿星，点按钮打开专属生日网站。
4. 网站：3D 吹蜡烛 → 祝福化作星座 → 祝福卡片墙 → AI 生成的专属寄语。
5. 有测试模式和演练命令，不用等真实生日就能走完全流程。

## 流程

```text
教务录入生日 ──► 每天 09:00 定时任务（Asia/Shanghai）
                    ├─ 生日在 3 天后 → 私信教务：「×× 老师 10/12 生日」+ 预填问卷链接
                    │                  学生 / 同事填写问卷 → 写入「生日祝福」表
                    └─ 今天生日     → 统计这一年的课表数据 + AI 生成寄语（写回老师表）
                                     → 群里发卡片，@ 老师，按钮打开生日网站
老师打开网站 ──► 云函数按 token 实时读取祝福（生日当天之后补交的也会出现）
```

每一步发完都在老师表里记下年份（「问卷已发年份」「祝福已发年份」），所以重复运行不会重复发送。2 月 29 日生日的老师在平年按 2 月 28 日处理；周末照常发送。功能上线时，如果有老师的生日在 3 天内（含当天），问卷当天补发。

## 系统组成

沿用现有 CloudBase 测试环境（`jingshi-test-d5gp401i44a0fa7a7`）的模式，新建 `apps/teacher-birthday`：

| 部分 | 做法 |
|---|---|
| `src/domain/` | 纯函数：找出今天要发问卷 / 要祝福的老师、在菁仕天数与蜡烛数、这一年的课表统计（计费课规则同薪资预警：有单价、时长 > 0、未临时取消）、页面 token（HMAC，老师记录 ID + 年份） |
| 云函数 `birthday-api` | ① 定时触发 `0 0 9 * * * *`：每日任务；② HTTP `GET /birthday-api/page?t=…`：校验 token，返回页面数据（只返回展示用字段，不含手机、微信、出生年份）；附件用飞书临时下载链接（24 小时有效，每次打开时重新获取） |
| 页面 | `app.jsjy.asia/birthday/?t=<token>`，静态托管；Vite + TypeScript + three.js，不用 React |
| 不建数据库 | 状态都放在飞书里，教务能直接看到、直接改 |

### 网站

1. **信封**：信封上写着「致 ×× 老师」，点击拆开。
2. **吹蜡烛**：3D 蛋糕，蜡烛数量 = 在菁仕的年数。对着手机吹气会熄灭蜡烛（用麦克风音量检测）；没有麦克风权限时改为长按 1 秒。蜡烛熄灭后，烟雾变成粒子升空。
3. **星座**：每条祝福是一颗星，连成以老师名字命名的星座；点星星会跳到对应的卡片。还没有祝福时，显示几颗点亮的星和「祝福还在路上」。
4. **卡片墙**：拍立得风格，点击翻面看留言，附件贴在卡片上（GIF 会动，视频点击播放）。
5. **结尾**：「在菁仕的第 N 天 · 这一年你上了 X 节课，陪 Y 位同学走过 Z 小时」+ AI 寄语 + 落款「菁仕教育全体」。

要求：能在飞书内置浏览器里运行；开启「减少动态效果」时直接显示静态画面；WebGL 加载失败时降级成 2D 页面，内容不能丢。学科专属装饰（物理粒子火焰、化学分子、数学函数曲线）放到二期。

### AI 寄语

生日当天的任务里生成一次：输入老师的姓名、学科、教学特点、个人介绍、这一年的数据，以及最多 20 条祝福原文；输出 80–150 字的中文寄语。要求：不提年龄，不编造成绩，语气温暖而不过分煽情，每位老师的寄语都不一样。生成结果写回「AI 寄语」字段。调用失败时使用内置模板寄语，09:00 的群消息照常发出。

接口：任意 OpenAI 兼容的 `chat/completions`，用 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` 三个环境变量配置。实际使用 DeepSeek 官方接口（`https://api.deepseek.com`，`deepseek-chat`）。CloudBase 自带的大模型网关在 2026-10-09 实测可以连通，但返回 `EXCEED_TOKEN_QUOTA_LIMIT`：套餐资源点不能抵扣大模型，Token 点产品已经下线。

## 测试模式与演练

- 测试环境就是「收件人配置」：`BIRTHDAY_ACADEMIC_OPEN_IDS` 只填徐翰超，`BIRTHDAY_GROUP_CHAT_ID` 填「生日通知测试」群。定时任务照常运行，教务录入的真实生日也会走一遍流程，但只会发给测试对象。
- 演练命令：`npm run rehearse -w @jingshi/teacher-birthday -- --teacher 汤朔 --step ask|celebrate|all`。它通过 `tcb fn invoke` 立即执行，不看日期，也不写「已发年份」，可以反复演练。
- 体验路径：运行演练 `ask` → 徐翰超收到私信 → 打开问卷，填几条祝福并上传表情包 → 运行演练 `celebrate` → 测试群收到卡片 → 打开网站。
- 上线：把这两个变量改成正式老师群的 `chat_id` 以及华心晨、Tinko 的 open_id，然后重新部署。

## 安全与隐私

- 网页不需要登录，靠 token 防猜（16 字节以上）；token 只针对单个老师的单个年份。用来生成 token 的密钥只存在云函数的环境变量里。
- 网页接口只返回展示用字段；勾了「隐藏」的祝福在服务端就被过滤掉。
- 飞书 App Secret 和 token 密钥都存在 `server.env` 里（不入 Git），格式和其他应用一致。
