设计说明（不进正式页面）

什么时候出这份纪要

随时录制结束时选「会议」→ 转写（不区分老师 / 学生，保留「说话人N」）→ 大模型输出下面的 JSON → 程序校验 → 这个页面渲染。App 里的「会议纪要」卡片、飞书私信和「复制纪要」用的纯文本，都由程序从同一份 JSON 拼出来，三处内容一致。会议不出家长总结和学情报告，不进「总结未发送」。

页面结构（顺序 = 会后最先要看的）

  1. 一句话总结 + 时长 / 议题 / 决定 / 待办四个数
  2. 决定事项：会上拍板的事，带时间点
  3. 待办事项：事项、负责人、截止、时间点；听不出负责人的标「待认领」
  4. 会议时间分布：按板块着色的时间轴 + 各板块用时
  5. 议题详情：板块 → 具体议题（一个学生、一个岗位、一条政策），每条有结论，「未定」标黄
  6. 待跟进：提出了但没结论的问题
  7. 发言占比：程序按转写里每个说话人的发言秒数算，不让大模型估

提示词（已上线：后台「提示词」第四栏「会议纪要」，可改可试可发布）

你是会议记录员，根据会议录音转写写一份结构化的会议纪要。
只写转写里有依据的内容，不编造人名、日期和数字；听不清、没结论的不要替它下结论，放进 followups。转写由机器识别，同音错字按上下文理解，不要照抄明显的错字。

字段要求：
- title：会议主题，15 字以内；lead：一句话总结，40 字以内，写最重要的结论或下一步
- sections：先把整场会分成 2–6 个板块（如「学生近况」「申请进度」「招聘」「制度与政策」）；每个板块下按时间顺序列出具体议题 items，每个 item 是一件具体的事（一个学生、一个岗位、一条政策），整场最多 40 个；start / end 照抄转写里的时间（mm:ss）；conclusion 一句话、30 字以内，没有结论写「未定」
- decisions：会上明确拍板的事，最多 15 条，挑最重要的；只是讨论、没拍板的不算
- todos：明确有人要去做的事，最多 20 条；owner 用转写里的称呼（如「郭老师」），听不出就留空；due 转写里说了才写
- followups：提出了但没有结论、需要会后确认的问题，最多 8 条

JSON（结构写死在代码里，后台只改上面的文字要求）

{
  "title": "", "lead": "",
  "sections": [{ "title": "板块", "items": [{ "title": "议题", "start": "mm:ss", "end": "mm:ss", "conclusion": "" }] }],
  "decisions": [{ "text": "", "time": "mm:ss" }],
  "todos": [{ "task": "", "owner": "", "due": "", "time": "mm:ss" }],
  "followups": [""]
}

程序兜底

  • 时间不合法的议题丢掉；板块为空的丢掉；提示词里限定条数，程序再兜底：决定最多 15 条、待办最多 30 条、待跟进最多 10 条；长会输出放宽到 8000 token，避免 JSON 被截断
  • 超过 1.2 万字的转写先分段整理（每段要求带时间线、决定、待办、未决问题），再汇总成 JSON
  • JSON 不合格让大模型重写一次，再不行记失败走重试

用真实录音试过

9 月 22 日那段 82 分钟的录音（文件名叫「课程录音」，内容其实是教务例会）：分成 7 个板块、60 个具体议题，28 条决定、21 条待办（大部分听得出负责人）、39 个待跟进。只给一层议题时，大模型要么把 58 分钟塞进一个议题、要么列出 35 条平铺议题，所以改成「板块 → 议题」两层。
