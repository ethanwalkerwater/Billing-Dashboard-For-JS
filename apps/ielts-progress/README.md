# 雅思正向率（ielts-progress）

老师在飞书表单录入学生的雅思基线、阶段模考和实考成绩，教务核验实考后，系统按课表找出每科的授课老师，算出每位老师的学生正向率（本次实考比上一次成绩高）。

页面有四个视图，共用时间（点选月份或区间）和科目筛选，所有表格点表头排序：

| 视图 | 看什么 |
|---|---|
| 总览 | 整体指标、老师对比、老师 × 科目 / 月份矩阵、全部明细 |
| 老师 | 选一位或几位老师并排比较：排名、样本、正向率、提分，按科目 / 按月份矩阵（首行是全体老师作参照），以及他们的学生明细 |
| 月度 | 选一个月：老师之间对比、老师 × 科目、和上月的环比 |
| 学生 | 每个学生各科最近一次的提分；点开看完整成绩记录（含阶段模考）和各老师带来的提升 |

- 登录与反馈追踪、薪资预警共用（`jsjy`，白名单表 `feedback_admins`）。
- 静态站点：CloudBase 托管 `/ielts/`；门户短链接 `jingshi.vercel.app/ielts` 在 `菁仕后台主页` 仓库里配 308。
- 设计与口径：[`specs/ielts-progress/design.md`](../../specs/ielts-progress/design.md)。

## 飞书

| 用途 | 地址 |
|---|---|
| 老师录入表单（发给老师） | <https://ccntnl19k0y3.feishu.cn/share/base/shrcnKvQvKlOwLxuOOz6KOTmrmK> |
| 「雅思成绩」表（教务核验、改错） | 课程表管理多维表格里的 `雅思成绩`（`tblbeqyLAlDVAGYJ`） |

表结构：学生（关联学员信息）· 成绩类型（基线 / 阶段模考 / 实考）· 考试日期 · 听力/阅读/写作/口语（单选 0–9，步长 0.5）· 成绩单（附件）· 已核验（仅教务）· 提交人 · 备注 · 听力老师/阅读老师/写作老师/口语老师（仅教务，留空按课表归属，填了以此为准，多位用「、」分隔）。
**字段不要改名**：同步前会检查字段表，缺字段直接报错并保留旧数据。

日常流程：老师提交 → 教务打开成绩单核对分数，勾「已核验」→ 打开网站（自动同步）或点「同步」。打开网站时先显示上次的数据，后台同步约 15 秒后自动刷新；5 分钟内同步过就不再自动同步。没有定时任务。没计入的记录都在页面顶部「待处理」里，点开能跳回飞书那一行。

## 口径

| 项 | 规则 |
|---|---|
| 样本 | 每次已核验实考的每一科，和该学生上一次该科有分的成绩（基线或更早的已核验实考）比；阶段模考只记录不比较 |
| 核验 | 实考勾了「已核验」才计入；没勾的按有无成绩单分到「待核验」/「缺成绩单」 |
| 结果 | 提分 = 正向；持平、下降分开统计 |
| 授课老师 | 「×× 老师」字段有值就用它；否则取课表中该学生、该科目，`上一次成绩日期 ≤ 上课日期 < 本次考试日期`，非临时取消 |
| 科目 | `雅思` = 四科全算；`雅思写作` / `雅思提高班-写作` 等按名字里的科目；刷题、试听、考试、模考不算 |
| 多位老师 | 每人各算一次；整体统计按样本去重 |

## 结构

```text
src/domain/progress.ts     全部规则（纯函数，前后端共用）
functions/ielts-api/       云函数：读「雅思成绩」+ 课表雅思课（服务端过滤，约 1700 行 / 15 秒）→ 写一行快照
migrations/                ielts_snapshots（一行 JSON 快照）+ RLS
src/web/                   看板
```

数据库只存原始数据快照，配对和统计在浏览器里现算：同步一次是一次 upsert（原子替换），打开页面只发一个查询。
