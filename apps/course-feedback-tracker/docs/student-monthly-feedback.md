# 学生月度课程反馈

教务每个课程月给每位学生发一个链接或二维码（短地址 `https://app.jsjy.asia/m/#2611.<学生档案ID>.<签名>`）。学生打开后看到本月要评价的老师，可以任选一位，逐份提交。问卷直接做在菁仕页面里（2026-11 起，不再嵌飞书表单：iPhone 微信里嵌入的飞书表单交不了），答案由云函数写回原飞书答卷表留档。退出后打开原链接，回到有草稿的那一题，或查看本月剩余任务。

链接绑定**学生档案 ID × 课程月**。例如 10 月课程的链接在 11 月打开，仍然评价 10 月课程。答卷继续按**学生 × 老师 × 课程月 × 作答身份**管理。同一位老师当月教了多门课时，列出课程名，合用一份答卷。教务按学生发放，评分按老师处理。

## 正式流程

- 首页深蓝页头写「11月课程反馈」、学生名和「已评价 x/y 位老师」，老师以卡片放在页头里（姓氏头像、课程、状态；下一位该评的老师白底突出），状态用文字 + 图形：虚线圈待评价、描边勾一方已评、实心勾双方已评。答题时顶部常驻菁仕品牌行、老师条（当前老师白底，可点换老师）和金色进度线。设计稿 [v9](./student-feedback-demo/compare.html?v=v9.html)。
- 一屏一题：先选身份（学生 8 题、家长 9 题，必答 3/4 题，身份题另算），单选点一下闪两下自动进下一题，多选和文字题点「确定」，可「上一题」。「其他」有补充字段的题（授课风格、改进方面）选了会出现输入框；「教学节奏」的「其他」在飞书没有补充字段，只是一个选项。电脑上可按字母键选、回车确定。
- 草稿按任务存在这台设备的 localStorage，重开链接回到那一题；连着评几位老师沿用上一次的身份（该身份已交的老师不预选）。
- 提交后圆章画勾 + 光环 + 纸屑约 1.5 秒，老师条状态弹一下，2 秒后弹感谢礼；没有感谢礼直接出现「继续评价下一位」。系统开了「减少动态效果」时只淡入、不撒纸屑（体验版忽略这个设置，方便看动效）。
- 教务在工作台复制链接、下载单张 PNG 或批量 ZIP，链接按学生档案 ID 和课程月签名，同一学生同月只有一个链接。已发出去的旧长链接（`/feedback/student.html#2026-11.…`）继续有效。标记学生已发时会更新该生当月所有未发任务。持有链接的人可填写对应学生的问卷。
- 重新「生成名单」后，原链接下一次读取时显示最新老师任务。不统计的老师和学生、已拒绝任务从待评清单排除。保留已提交任务及其课时。新课程月用新链接；按上海时区，最迟在课程月 M+2 月初停止收集，提前发布定稿也会关闭该月入口。

## 接入与验收

学生页是静态入口 `/m/`（和 `/feedback/student.html` 同一个页面，`deploy:web` 一起发），签名放在 URL 片段里。浏览器通过同域 `POST /auth/monthly-feedback` 携带签名：不带 `taskId` 读名单；`action: "submit"` 交一位老师的答卷；`action: "thanks"` 送感谢礼。读名单不返回评分、答卷内容或飞书记录 ID。

提交时 `feedback-api`：

1. 按 [题目定义](../src/domain/monthly-questions.ts) 白名单校验身份、字段、选项和长度（建议 500 字、「其他」200 字），另一分支的字段一律拒收。
2. 该身份已交过的直接返回成功（网络断了重交不会写两份）。
3. 读答卷表字段（每个函数实例缓存 10 分钟），和题目定义比对；对不上就私信 `FORM_ALERT_OPEN_IDS`（开发徐翰超），同一组差异每个实例只发一次。飞书里已经没有的字段不写，其余照常写入。注意：写入不存在的选项时飞书会**悄悄新建一个选项**，所以改题必须两边一起改。
4. 在答卷表新建一行（学生姓名、老师姓名、反馈课程月份、身份 + 各题），再用现有 `confirm_monthly_feedback` 把这条记录绑到任务上，所以感谢礼资格、工作台进度、评分对账都和以前一样。提交时间是飞书自动的创建时间。

旧的 `action: "confirm"`（去飞书搜答卷再确认）保留，给还开着旧页面的人用。

**改题流程**：先改飞书答卷表 → 改 `src/domain/monthly-questions.ts`（字段名和选项一字不差）→ `npm run check:questions -w @jingshi/course-feedback-tracker`（只读比对线上表，输出「一致」才算过）→ 部署 `feedback-api` 和网页。

验收：`.team/tasks/20261125-monthly-feedback-native/page-selfcheck.cjs` 在手机尺寸走完体验版全流程（草稿恢复、连点只进一题、身份沿用、感谢礼、电脑字母键），再用模拟接口检查正式请求体、断网重交、减少动态效果；`PAGE_URL=https://app.jsjy.asia/m/` 可直接测线上。`tests/monthly-submit.test.ts` 覆盖校验、写入、绑定、重交、告警；`tests/feedback-thanks-native.sql` 在本地库验证「提交 → 感谢礼进后台记录表」。

## 感谢礼与教务处理

每位老师的答卷确认后，学生或家长可以选一份由菁仕教育出资的礼物，再选一句感谢语或自己写一句（最多 200 字）。点「暂时不用」或关闭弹窗会继续评价下一位老师。同一学生、课程月、老师共用一次送礼机会。重复提交只保留第一次送出的记录。后台调整名称、价值或停用礼物后，尚未送出的旧选项会提示重选。

菁仕教育飞书团队成员首次登录即可使用[感谢礼管理](https://app.jsjy.asia/feedback_thanks/)。所有成员可按课程月查询、按学生或老师搜索，选中记录后批量标记已处理或恢复待处理，也可单条改回。奖品由教务人工安排。「礼物设置」可编辑四个礼物位的名称、说明、参考价值、启用状态，选择 JPG、PNG 或 WebP 图片（最大 5 MB）后预览、保存。图片在浏览器压缩，历史记录保留送出当时的名称、价值和留言。

首次发布先应用 [感谢礼迁移](../migrations/202611230001_feedback_thanks.sql)，随后应用[飞书团队成员访问策略](../migrations/202611230002_feedback_thanks_team.sql)，再发布现有 `feedback-api`、学生页面及 `npm run deploy:thanks` 管理入口。排查未显示邀请时，先确认该老师答卷、本月收集状态、有无启用礼物，以及该任务是否已登记。教务处理失败时检查账号是否已通过本团队飞书登录和数据库更新回执。

[教务体验版](https://app.jsjy.asia/m/#demo)（旧地址 `/feedback/thanks-demo.html` 会跳过来）用的是同一个学生页：虚构学生小禾、陈老师（两门课）、许老师、周老师（家长已评）。答案和感谢礼只存在这台设备上，不调云函数、不写飞书、不进感谢礼后台；首页底部「重新开始体验」清空重来。

## 运维成本

- 打开链接：一次函数调用 + 一次数据库读取，和以前一样。
- 提交一位老师：一次函数调用（约 1–1.5 秒：读字段（有缓存）、写一行飞书、一次数据库事务）。代替了以前的「我已提交，确认进度」（那次要去飞书搜答卷），次数和以前的确认差不多。按一轮 258 份答卷、512 MB 估算，函数 + 数据库 API 约 **20 点/月**，另计 PostgreSQL 活跃时段（和以前同一批操作，不新增时段）。
- 感谢礼：不变，约 12 点/月。
- 问卷对不上的告警：跟着提交走，不加定时器、不轮询；飞书接口不占 CloudBase 资源点。
- 体验版：纯静态页，0 点。
- 人工：改题时多一步 `npm run check:questions`。答卷写入后飞书的「记录变化」事件是否触发没有验证（不影响：提交时已直接绑定任务，评分在每天 03:00 对账或工作台「刷新反馈」时更新）。
- 排查：提交失败先看 `tcb fn log feedback-api`；「问卷和飞书答卷表对不上」的日志和徐翰超收到的私信列出了具体差异。

## 开发记录

- **11-25** 起因：iPhone 微信里嵌入的飞书表单交不了（iOS 拦第三方 Cookie）。定下原生问卷：一屏一题、按老师分别提交、答卷照旧写回飞书答卷表、评完接感谢礼。设计稿 v4–v8。
- **11-26 上线**：v9（首页老师卡片放进深蓝页头，去掉假的微信灰色标题栏）。短链 `/m/#YYMM.学生ID.16位签名`（63 字符，旧长链照认）；教务体验版 `/m/#demo`；提交时比对飞书字段，对不上私信徐翰超。感谢礼后台不用改。
- **11-26 设计评审**：和 Codex 互评 4 轮（Codex 7.4 → 8.6 → 8.9 → 9.1，我方 9 分）后重新部署。改了：
  - 兼容：旧版 iOS 微信没有 `AbortSignal.timeout`（改用手动计时，读完响应体才停表），没有 `<dialog>` 时不弹感谢礼。
  - 交互：单选后立刻点「确定」不再跳两题；选填题没答时按钮写「跳过」；电脑中文输入法回车不误提交；「已经很好了」和具体改进项互斥；提交页写「已答 7 题，跳过 1 道选填题」。
  - 草稿：打字时刷新回到原题；家长和学生共用手机时草稿按身份分开（`draft.<任务>.<身份>`），「继续评价」沿用刚提交的身份从第一题开始。
  - 版面：手机上题目顶对齐，按钮不随选项多少跳动；首页进度按这台设备提交过的身份算，没提交过显示「X/N 位老师已有反馈」；课程名换行不截断；感谢礼信封图提交时预加载。
  - 无障碍：浅灰字和占位字调深、感谢语选项 44px、进度条有读屏数值、弹窗关后焦点到「继续评价」、减少动态效果时关掉闪烁和弹跳。
  - 没改：提交后自动弹感谢礼（业务流程）、纸屑动效（已定设计）。
- **待办**：真机 iPhone 微信验收；正式答卷表写一条测试数据（待用户确认）；飞书「记录变化」事件对 API 写入是否触发。

## 参考产品

- Harvard Q 的同一入口展示可评价课程、状态、截止日，并能恢复填写中问卷。借用它的个人清单和续填规则。[Harvard Q](https://q.fas.harvard.edu/evaluate-course)
- 宾大的每份课程评价独立提交，开放期内可续填，提交后锁定。借用独立提交和提交后确认的规则。[Penn 课程评价学生指南](https://cetli.upenn.edu/resources/evaluations/end-of-semester/student-faqs/)
- SJSU 的 Explorance Blue 在提交后展示仍开放的评价，并标明每组题对应的老师。菁仕进一步直接打开下一位，同时保留返回名单的入口。[SJSU 课程评价学生指南](https://www2.sjsu.edu/teachingeval/faqs-students/index.php)
